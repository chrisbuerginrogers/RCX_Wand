# LASM examples

Five real RCX programs, in increasing order of what they touch, written
against [`tools/lasm_compiler.py`](../tools/lasm_compiler.py)'s dialect
(see that file's own docstring for where the compiler came from and what
it's verified against).

Each file is a small Python module carrying its own LASM source as a
string, so the program and the thing that runs it are one readable file
— there is no separate generated bytecode module any more.

| File | Adds |
|---|---|
| [`01_hello_beep.py`](01_hello_beep.py) | One command: play a sound. |
| [`02_tune.py`](02_tune.py) | Several commands run once, in order. |
| [`03_loop_forever.py`](03_loop_forever.py) | A label + `jmp` — the first loop. |
| [`04_read_sensor.py`](04_read_sensor.py) | Reads a sensor, branches on it with `chk`. |
| [`05_motor_follow.py`](05_motor_follow.py) | Same sensor read, but drives a motor instead of a sound. |

Each file's own comments explain the opcodes it introduces — `chk`'s
backwards-feeling branch direction and the `dir` mode/direction mismatch
this project found on real hardware are both called out where they
matter (`04` and `05` respectively).

## Running

From the Mac, with the StickS3 plugged in over USB and its IR window
pointed at the RCX a few inches away. Either form works:

```
python3 run_on_rcx.py examples/01_hello_beep.py
python3 examples/01_hello_beep.py
```

The Mac compiles; the Stick transmits. Nothing needs building or
deploying first — `run_on_rcx.py` pushes the driver itself.

`--no-start` downloads a program without starting task 0:

```
python3 run_on_rcx.py examples/03_loop_forever.py --no-start
```

`04`/`05` expect a light/reflection sensor wired to sensor port 0.

## Writing your own

Copy any of these, or skip the wrapper entirely and hand
`run_on_rcx.py` a bare `.lasm` file:

```
python3 run_on_rcx.py my_program.lasm
```

Labels are scoped to the `task`/`sub` they appear in, so reusing
`Label0` across several tasks is fine. `prgm N` selects which program
slot the tasks after it download into, and that ordering is preserved
exactly as written.

## Status

Compiled output checked against the compiler (chunk sizes, checksums,
and `05`'s backward loop-jump distance all verified correct), and the
same acked block-transfer path has carried a full firmware download to
a real RCX. These five have not yet had a clean end-to-end run on
hardware — see CLAUDE.md's "What is still marginal" for why reply
decoding is currently the limiting factor.
